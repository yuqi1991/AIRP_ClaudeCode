# 产品原则

## 1. 玩家拥有设定

玩家应能在游玩中修改角色、故事、世界书和变量。引擎负责让修改可见、可追溯并影响后续回合，而不是把卡片当不可变 prompt。

## 2. 长期连贯优先于单回合华丽

状态、记忆、角色关系、世界时间和未落地伏笔必须能跨会话延续。短期高质量描写不能以破坏角色一致性或状态可信度为代价。

## 3. 卡片是可解释的数据，不是黑箱 prompt

导入过程应把角色卡分解为开场、世界书、变量、前端资产和兼容诊断信息。失败时应说明哪部分无法承载，而不是静默丢失。

## 4. 世界书像 skill 按需加载

世界书条目通过 `title — usage` catalog 供叙事 agent 选择；需要时加载原文。避免每轮预塞全文，保持上下文成本和检索意图可控。

## 5. 多 agent 按职责分工，不按文件分工

未来一等职责：

- **叙事导演**：决定本轮场景、NPC 反应、节奏和可选行动；
- **世界模拟**：推进后台 NPC、时间、事件、伏笔和世界状态；
- **角色演化/文风润色**：维持角色声口、关系演变、风格约束和最终文本质量。

每个职责应拥有清晰输入、输出、状态权限与失败模式，避免多个 agent 无约束改写同一事实。

## 6. 资料可自主补全，但必须可追溯

当角色资料明显不足且叙事需要时，agent 可以自主使用 Web Search 等工具补充作品/角色资料；必须记录来源、提取摘要、适用范围和不确定性。外部资料不能覆盖玩家本地设定，除非玩家明确采纳。

## 7. 代码与文档同改

任何改变产品行为、模块 interface、数据格式或路线图的改动，必须同步更新 wiki、功能状态表和必要 ADR。文档不是发布后的说明，而是协作 interface 的一部分。
