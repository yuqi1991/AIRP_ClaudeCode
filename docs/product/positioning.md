# 产品定位与边界

## 定位

AIRP 是一个**玩家优先的本地独立 RP 引擎**。它让玩家导入、游玩、调试和实时修改角色卡、世界书与故事设定，并在长期剧情中获得连贯叙事、可追踪状态和持续演化的世界。

它同时提供：

1. **角色卡/世界书运行与管理**：兼容并承载既有卡片资产，逐步提高导入诊断和编辑能力。
2. **长期叙事引擎**：用户输入驱动回合，状态、记忆、剧情规划和后台 NPC 随回合发展。
3. **多 agent 编排**：未来由不同 agent 分别承担叙事、世界模拟、角色演化和文风润色。

## 第一目标用户

长期游玩的 RP 玩家。

玩家应能：

- 导入或选择卡片素材；
- 在浏览器中持续游玩；
- 查看并回退、重roll回合；
- 在游玩中直接修改角色、故事、世界书和变量设定；
- 让修改即时影响后续叙事，而不是只能重新开局。

角色卡作者和协作开发者是重要次级用户：前者需要可诊断的兼容与调试能力，后者需要可信的架构事实和稳定的模块接口。

## 当前版本的角色

当前版本是 **Claude Code 直驱原型**：Claude Code 通过本地 Python/HTTP bridge 驱动导入、上下文准备、叙事生成和交付。它证明了卡片导入、MVU、记忆、前端互动和世界书 skill 模式的价值，但不是长期 runtime 方案。

## 非目标

当前不承诺：

- 云端托管、多用户协作或公网服务；
- 多实例并行运行；
- 对任意 SillyTavern 卡片的完全兼容；
- 不经来源记录的外部资料混入设定；
- 将 Claude Code 的 transcript/loop 机制作为正式产品依赖。

## 未来独立化

下一代保留已有资产和经验，但替换 runtime/harness，使系统能：

- 精确控制上下文装配，而不依赖追加式 Claude Code transcript；
- 自主调度 agent、工具和用户输入；
- 支持更清晰的多 agent 通信；
- 降低 `wait_pending` loop 和人工 session 管理带来的不稳定性。
