# AIRP: 集成式游戏工作区、Studio 抽屉与 Monitor

## Problem Statement

AIRP 当前的游玩界面与 Studio 配置体验割裂，Studio 作为独立页面会打断剧情上下文；运行状态、Token、生成状态和编排信息也没有在同一工作区内形成可读、可调试的反馈。现有界面无法让玩家在保持沉浸的同时修改角色卡、开场、世界书绑定和编排配置，也无法让创作者判断某个 Agent 的实时输出、工具调用和最终 Artifact 为什么产生。

本规格将游戏作为唯一主工作区：Studio 通过顶栏向下展开的互斥动态抽屉集成进游戏界面，右侧 Monitor 持续观察当前存档和 Agent Graph。第一阶段保留当前线性 Graph Runtime，使用自上而下的 DAG 风格视觉呈现，不改变运行语义。

## Solution

AIRP 使用统一暗色工作台视觉：深海军蓝背景、低饱和金色强调、暖白色正文、细边框和适合长篇阅读的衬线文本。品牌统一为 `AIRP`，界面文案以中文为主，`Agent`、`Graph`、`Provider`、`Regex Collection`、`Token` 等领域对象保留英文名称。

游戏界面由三块组成：顶部导航、左侧主对话区、右侧 Monitor。顶部只显示 AIRP、当前游戏和五个入口：`游戏`、`世界书`、`Agents 与编排`、`Regex Collections`、`模型`。点击入口打开唯一的 Studio 抽屉宿主；点击另一个入口替换内容，点击当前入口、关闭按钮或 `Esc` 关闭。桌面端抽屉从顶部向下展开，覆盖左侧主工作区约 `72vh`，底部保留少量对话上下文，右侧 Monitor 保持可见；移动端占满顶栏以下空间。

游戏抽屉左侧浏览、搜索、导入和切换已导入的游戏，右侧编辑当前游戏的 `角色卡`、`开场`、`世界书绑定`、`编排选择`。游戏切换恢复目标游戏最后使用的存档会话；生成中切换需确认，确认后先取消并等待终态，取消则保留当前游戏。未保存表单切换时直接丢弃，不做复杂脏状态机制。应用启动恢复上次游戏和存档，没有游戏时自动打开游戏抽屉的导入空状态。

主对话采用长文优先的混合排版：AI 叙事接近全宽、弱边框、衬线正文；玩家输入右对齐并使用金色描边。Markdown 保留段落和换行，支持加粗、斜体、删除线、H1-H3、列表、引用、链接、行内代码、代码块、分隔线和 GFM 表格。表格只在自身容器内横向滚动；Markdown 图片禁用，原始 HTML 转义。输入区固定底部，textarea 最多约六行，生成时发送按钮原位切换停止按钮，行动选项只填入输入框。历史消息提供复制、重 roll、回退等轻量操作。

Monitor 固定在右侧，显示当前存档名称、Revision、最后保存时间及切换、新建、重命名、删除操作；生成期间禁用存档管理。Monitor 始终显示当前游戏的完整 Graph，节点自上而下排列，状态为未运行、等待、运行中、成功或失败，运行结束后保留最近结果。运行中 Agent 节点使用克制的金色高亮和流动边；点击已开始节点，在左侧主对话上方打开唯一的大型调试浮窗，实时展示文字流、模型调用、工具调用、最终 Artifact、错误和 Token。点击其他节点直接替换内容，支持关闭和 `Esc`，不支持拖拽、缩放、最小化或多窗口。

Studio 各抽屉的工作区如下：`世界书` 管理 Definition、条目和启用状态；`Agents 与编排` 分为 `Agents` 和 `编排` 两个标签，分别编辑 Agent instruction、模型、工具和 Regex Collection 绑定，以及维护线性 Graph 的节点顺序和输出节点；`Regex Collections` 管理全局可复用、有序、面向 input/output/both 的 JavaScript RegExp 规则；`模型` 管理 Provider Profile、API format、密钥状态、模型目录、连接测试和刷新。Regex Collection 遵循既有领域规格：每个 Agent 可绑定零或一个 Collection，规则在 Execution Plan 创建时冻结，输入转换在宏展开前、输出转换在完整模型文本后，原始值、转换值和逐规则诊断进入 Node Run，错误使当前节点和 Graph Run 失败。

实现只补充完成集成工作区所需的最小运行契约：切换活动 Project、取消进行中的生成、恢复目标 Project 最后活动的 Session、返回游戏快照，以及提供 Monitor 所需的 Graph/Trace 快照。Project 内容、Session、活动 Graph 选择和全局 Studio Library 保持既定所有权边界；不借此重写 Runtime。

## User Stories

1. 作为玩家，我希望打开应用后直接进入上次的游戏和存档会话，以便继续剧情。
2. 作为玩家，我希望浏览所有已导入游戏并点击切换，以便在同一界面选择不同角色卡项目。
3. 作为玩家，我希望游戏切换恢复目标游戏最近使用的存档，而不是创建空会话。
4. 作为玩家，我希望没有任何游戏时看到明确的导入入口，而不是空白或错误页面。
5. 作为玩家，我希望生成进行中切换游戏前看到确认，以避免意外中断。
6. 作为玩家，我希望确认切换后生成被取消且不提交半成品，目标游戏随后正常加载。
7. 作为玩家，我希望取消切换确认后仍停留在当前游戏和当前会话。
8. 作为玩家，我接受未保存 Studio 表单在切换游戏时直接丢弃，以换取简单可预测的工作流。
9. 作为玩家，我希望顶部只看到 AIRP、当前游戏和五个清晰入口，不被 Token 或连接装饰打扰。
10. 作为玩家，我希望点击顶部入口时抽屉从顶部向下展开，并保留对话和 Monitor 的上下文。
11. 作为玩家，我希望任意时刻只有一个 Studio 抽屉，以避免多个配置层相互遮挡。
12. 作为玩家，我希望点击另一个入口时直接替换当前抽屉，点击当前入口或 `Esc` 关闭抽屉。
13. 作为移动端玩家，我希望抽屉填满顶栏以下空间，同时仍能返回游戏。
14. 作为玩家，我希望在游戏抽屉中编辑角色卡正文、角色名和受控视觉资产。
15. 作为玩家，我希望在游戏抽屉中编辑开场并选择可用开场。
16. 作为玩家，我希望在游戏抽屉中绑定和排序多个 Worldbook Definition。
17. 作为玩家，我希望在游戏抽屉中选择当前游戏使用的 Graph，且该选择独立于角色卡内容保存。
18. 作为创作者，我希望世界书抽屉支持导入、新建、复制、重命名、编辑、启用和导出。
19. 作为创作者，我希望世界书条目列表可搜索、排序并快速切换启用状态。
20. 作为创作者，我希望 Agents 抽屉显示 Agent 列表、instruction、Prompt 预览、Provider、模型参数、工具权限和 Regex Collection 绑定。
21. 作为创作者，我希望从 Graph 节点点击进入对应 Agent 定义，并自动定位到该 Agent。
22. 作为创作者，我希望编排抽屉显示 Graph 列表、垂直线性拓扑、节点设置和明确的 output node。
23. 作为创作者，我希望调整节点顺序、启停节点并看到节点引用的 Agent。
24. 作为创作者，我希望 Regex Collections 抽屉按顺序编辑规则、启停规则、移动规则并运行测试输入。
25. 作为创作者，我希望 Regex Collection 支持 input、output 和 both 目标，并能看到逐规则诊断。
26. 作为创作者，我希望修改 Regex Collection 后只影响下一次 Graph Run，正在运行的 Execution Plan 不被改变。
27. 作为创作者，我希望无效 JavaScript pattern、flags 或转换错误明确显示在失败 Node Run 中，而不是静默回退。
28. 作为创作者，我希望模型抽屉支持多个 Provider Profile、Responses/Chat Completions API format、密钥状态、模型目录和连接测试。
29. 作为玩家，我希望 Monitor 显示当前存档名称、Revision 和最后保存时间。
30. 作为玩家，我希望在 Monitor 中切换、新建、重命名和删除存档会话，并在生成期间看到这些操作被禁用。
31. 作为创作者，我希望 Monitor 始终展示完整 Graph，即使当前没有运行。
32. 作为创作者，我希望运行中的 Agent 节点明显高亮，节点状态和执行边能以克制动画表达。
33. 作为创作者，我希望点击已开始的 Agent 节点打开一个足够大的调试浮窗，而不是跳转到新页面。
34. 作为创作者，我希望调试浮窗实时显示模型文字流、工具名称、参数、结果、耗时和错误。
35. 作为创作者，我希望调试浮窗显示最终生效的 instruction、Provider、模型、生成参数、Prompt 来源、Artifact 和 Token。
36. 作为创作者，我希望浏览器刷新或短暂断线后，节点详情能从持久 Trace 恢复，而不是回到空白。
37. 作为玩家，我希望对话正文正确处理 Markdown、段落、换行和表格，不影响整体布局。
38. 作为玩家，我希望 Markdown 内容不能执行原始 HTML 或加载任意图片。
39. 作为玩家，我希望 AI 消息可复制、重 roll 或回退，玩家消息可复制或回退，并在改变历史时看到简短确认。
40. 作为玩家，我希望行动选项点击后填入输入框而不是直接发送。
41. 作为玩家，我希望生成时发送按钮变成停止按钮，停止后输入区状态清晰可恢复。
42. 作为触屏用户，我希望消息操作收纳在省略号菜单，避免悬停专属交互。
43. 作为键盘用户，我希望抽屉、标签、表单和调试浮窗可完整操作并有明确焦点。
44. 作为低动效偏好用户，我希望 `prefers-reduced-motion` 下不出现持续呼吸、流动边或大幅展开动画。
45. 作为维护者，我希望 Graph 视觉边界允许未来扩展分支和并行，但本阶段不会伪装成已支持的 DAG Runtime。

## Implementation Decisions

- 以当前 rebase 后的 deep-module Runtime 作为基线；本功能属于浏览器应用壳、最小 HTTP/API 契约和现有 Graph/Node Run 观察层，不重写 Graph Runtime。
- 用单一 `StudioDrawerHost` 管理五个入口的互斥状态、打开/关闭/替换、键盘关闭和响应式布局。桌面端只覆盖主对话区，Monitor 不被卸载；移动端改为顶栏下全屏工作区。
- 使用单一暗色 token 集和 AIRP 品牌；删除主题切换、顶部 Token、生成状态和连接装饰。所有状态性信息由 Monitor 承担。
- 将 Project、Session、活动 Graph 选择、Studio Library 和 Execution Plan 的所有权分开。游戏切换接口必须在取消生成并等待终态后完成 Project/Session 恢复。
- Monitor 消费统一的游戏快照、Graph 状态和 Node Trace 事件；它不编辑 Studio Definition。Graph 可视化组件只表达既有线性拓扑，不创建新的运行语义。
- 调试浮窗采用单实例覆盖层，节点选择是替换关系。SSE 只传递激活、状态和文本 delta 等实时事件；完整 Prompt、工具结果、Artifact 和错误通过按需详情接口加载。
- Markdown 使用安全解析和渲染边界：转义原始 HTML，拒绝 Markdown 图片，表格内部滚动；角色卡和受控资产沿用独立渲染路径。
- 输入和历史操作维持现有会话语义；停止生成必须调用已有取消机制，重新生成或回退必须创建清晰的历史变更结果。
- Agents、编排、Worldbook、Regex Collections 和模型编辑器共用工作台表单约定，但每个抽屉拥有自己的列表、编辑和保存边界。未保存编辑只存在于当前抽屉。
- Regex Collection 完全遵循既有规格：全局可复用、每个 Agent 零或一个绑定、JavaScript RegExp source/flags/replacement、规则有序执行、运行时冻结、原始/转换值与诊断持久化、无效规则失败、不提供自动重试或 Project 级正则配置。
- Provider Profile 的 API Key 只保留“已配置”状态给浏览器；它不进入 Graph、Execution Plan、Trace、日志或导出文件。
- 删除被引用的 Studio Library 对象时返回引用列表并阻止删除；复制对象生成新稳定标识，引用不会隐式迁移。
- 过渡期间任何旧的独立 Studio 导航只能作为兼容入口，最终行为必须回到集成式游戏工作区；产品主流程不再依赖独立 Studio 页面。

## Testing Decisions

测试分为三层，并以外部行为为边界，不锁定私有 CSS class 或组件内部实现。

1. 浏览器层使用 Playwright 覆盖桌面和移动视口：顶部五入口、顶部向下抽屉、互斥替换、游戏切换、Monitor、Graph 节点高亮、单实例调试浮窗、实时 Trace、Markdown 和 GFM 表格、消息操作、生成/停止、键盘焦点、`Esc`、触屏菜单、空状态和错误状态。使用截图断言检查参考风格、阅读密度、抽屉与 Monitor 不重叠，以及移动端无横向页面溢出；补充 `prefers-reduced-motion` 场景。
2. Runtime HTTP/API 层使用契约测试覆盖 Project 切换、Session 恢复、生成取消、活动 Graph 选择、游戏快照、Monitor snapshot、Node Trace 详情和 Studio CRUD。验证生成期间存档管理被拒绝、切换取消后不提交半成品、删除引用对象返回明确冲突。
3. Graph/Node Run 层复用现有执行测试，覆盖线性拓扑状态迁移、节点流式 Trace、工具调用记录、失败停止、最近运行保留、断线恢复，以及 Regex Collection 的 input/output/both 顺序、JavaScript 语义、规则冻结、原始/转换诊断和失败行为。

浏览器测试应验证可见文本、角色和可操作结果，不验证具体 DOM 层级、类名、动画实现或某个 CSS 数值。视觉测试必须至少覆盖一个桌面宽度和一个移动宽度；表格测试必须证明滚动发生在表格容器内而非撑宽主对话。

## Out of Scope

- 任意 DAG Runtime，包括分支、并行、条件边、循环、合并和自动调度策略。
- Graph Runtime、Node Runner、Provider Adapter 的整体重写。
- 完整运行历史浏览器、版本管理、配置 diff、自动保存、未保存修改确认和复杂恢复机制。
- Markdown 图片、原始 HTML 执行、任意脚本、外部资源自动加载。
- 多主题、主题切换和与参考图无关的装饰性动效。
- Project 级 Regex Collection、Turn Adapter 或隐式故事标签协议。
- 一个 Agent 绑定多个 Regex Collection、运行期间编辑冻结配置、自动跳过规则、自动重试或 fallback 模型。
- 调试浮窗的拖拽、缩放、最小化、多窗口并排和独立路由。
- 移动端同时展示三栏；移动端采用列表到详情的 master-detail 交互。
- 将 Monitor 扩展为 Studio 设置表单或把存档管理散落到顶部导航。

## Further Notes

- 该规格与 `ADR-0020` 共同定义集成式工作区；领域事实以现有 Agent Studio 架构文档和 Regex Collection 规格为准。
- “游戏”指 AIRP Project，“存档会话”指 Session；文案和 API 命名不得混用两者。
- Monitor 的 DAG 风格只是线性 Graph 的可视表达，节点内部模型调用和工具调用不会伪装成额外拓扑节点。
- 本规格发布后，后续实现代理应先完成工作区壳、Monitor 数据形状和浏览器测试骨架，再接入各 Studio 抽屉；每个阶段都应保持游戏主对话可运行。
- 完成后应同步更新状态文档、相关 ADR 和用户可见的变更说明，并保留两张参考图作为视觉验收依据。
